\section{Introduction and System Overview}

\subsection{Project Context and Objectives}
Older adults benefit from hands-free access to time, medication information, and caregiver-supported routines. At the same time, commands that change health-related state must resist accidental or unauthorized execution. Dearly addresses this tension with the following objectives:
\begin{itemize}
    \item provide voice-based interaction in Vietnamese through an accessible Android interface;
    \item provide a public general-information mode without a Dearly or Firebase session;
    \item require successful SV before a medication dose is marked as taken; and
    \item use SID for safe personalization, limited to a caller's trusted caregiver--elder group.
\end{itemize}

\subsection{\hspace{0.15em}System Architecture}
Figure~\ref{fig:architecture} shows the production design. Android is the only public client. It records audio, sends it to the Go API, displays the response, and uses Android's local \texttt{vi-VN} TextToSpeech engine for output. The Go API authenticates sessions, manages enrollment and medication state, and calls the private FastAPI service. The AI service runs ASR, ECAPA embedding extraction, SID, SV, and constrained LLM/local intent analysis. PostgreSQL is authoritative for user, relationship, medication, enrollment, and grant data; Kafka delivers domain events to the notification worker.

\subsection{Voice-Request Processing Flow}
For a medication confirmation, the read-back includes both the matched medicine and its scheduled time before Dearly accepts a fresh ``Đúng rồi'' response.
For public queries, Android posts audio to a separate unauthenticated endpoint. The API permits only \texttt{ASK\_TIME}, \texttt{ASK\_DATE}, greeting, and usage guidance; it never loads enrollment, medication, contact, or relationship records. For authenticated queries, the AI service transcribes the recording with Whisper, identifies a speaker when trusted profiles are supplied, and classifies the request. The API enriches \texttt{ASK\_TIME}, \texttt{ASK\_DATE}, and \texttt{CHECK\_MEDICATIONS} from local time or PostgreSQL. A spoken \texttt{MARK\_TAKEN} request includes the medicine name: Android finds the matching unpaid dose, asks the elder to say ``Đúng rồi,'' and verifies that confirmation recording against the signed-in elder. Only a successful SV result creates a grant; therefore ASR, intent classification, and SID alone never authorize a medication update.
